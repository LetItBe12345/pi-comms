# 阶段 22：多 Agent 显式并行投递

状态：已完成

目标：允许用户或 Agent 在一条公开消息开头连续 `@` 多个 Agent，并把同一正文独立、并行地投递给所有有效目标；不增加父子任务、整体进度或自动汇总。

依赖：阶段 21

## 实施项

- [x] 先把多 `@` 语法、混合目标、部分失败、通信轮数和验收要求写入 `SPECIFICATION.md`。
- [x] 解析消息开头连续出现的多个 `@名称`，正文从最后一个前置 mention 后开始；正文中间的 `@` 继续作为普通文本。
- [x] 同一消息中的重复目标按成员 ID 去重，只投递一次。
- [x] 一条公开消息保存全部 `mentionIds`，群聊时间线只显示一条原始消息。
- [x] 对每个目标 Agent 创建独立 `requestId`、ACK、权限判断、投递状态、结果去重和失败状态；这些请求共享原始消息 ID 和通信链 ID，但不建立父子任务关系。
- [x] 所有目标收到相同任务正文，并收到 `coRecipients`，列出本次同样收到任务的其他 Agent。
- [x] Prompt 明确：共同接收者可能仍在排队或等待批准；Agent 不得假定对方已开始或已完成，也不应把原任务原样再次转给共同接收者。
- [x] 各目标按各自 Session 的现有 FIFO 队列处理；不同 Session 可并行，同一 Session 继续串行。
- [x] 每个目标独立执行 `auto | approval | blocked` 权限规则。一个目标离线、拒绝或失败不得取消其他目标。
- [x] 为同一公开消息展示可理解的逐目标状态和失败原因，但不增加整体任务进度、父任务页面或自动汇总结果。
- [x] 用户同时 `@用户` 和 `@Agent` 时，用户 mention 只用于公开提醒，Agent mention 创建投递；只有用户 mention 时仍按普通公开消息处理并允许 Proactive Router 判断。
- [x] Agent 最终回答允许开头连续 `@` 多个其他 Agent，复用相同多目标投递规则。
- [x] 多目标 Agent-to-Agent 转交沿用同一个 `chainId`，每批成功创建的下一跳计为同一轮，继续受现有 10 轮暂停规则约束。
- [x] 禁止向自己投递；一批中的自身目标失败不得阻止其他目标。
- [x] Agent 回答分别公开，不等待全部完成，不自动合并，不自动选择汇总 Agent。
- [x] 覆盖多目标成功、重复 mention、部分离线、部分审批、部分拒绝、断线重投、重复 ACK、Agent 多目标下一跳、10 轮暂停和 TUI 状态测试。
- [x] 更新 README 中多 Agent 显式调用和协作示例。

## 完成条件

- [x] 一条消息可以同时投递给多个 Agent，且群聊只显示一条原始消息。
- [x] 每个目标独立可靠投递、执行和返回结果，部分失败不影响其他目标。
- [x] 每个 Agent 知道本次共同接收任务的其他 Agent。
- [x] 产品中不出现父子任务、整体进度或自动汇总概念。
- [x] Agent-to-Agent 多目标通信不会绕过权限、FIFO 或 10 轮暂停规则。
- [x] `npm run check` 通过。
